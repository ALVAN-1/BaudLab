# BaudLab 团队服务器

这是管理员部署包。普通成员安装客户端，无需各自运行服务器。包内 `VERSION.json` 标记发布版本，不含生产数据库、访问令牌或 SMTP 配置。

1. 在一台成员可访问的电脑安装 Node.js **22.13 或更高版本**。使用内置 SQLite，无需 `npm install`。
2. 解压全部文件到固定目录，例如 `D:\BaudLab-Server`；不要只复制 `server.js`。
3. Windows 双击 `start-server.bat`；Linux/macOS 执行 `sh start-server.sh`。控制台应保持运行；端口已被占用时排查现有服务，脚本不会杀进程。
4. 管理员在服务器本机打开 `http://localhost:3010/admin`，设置团队访问令牌、SMTP 和备份策略。管理页面只允许本机访问。首次启动生成 `server.config.json` 和 `server-data/`。
5. 成员在客户端「数据库连接」页填写 `http://服务器内网IP:3010` 与相同令牌，测试后保存。防火墙允许团队内网访问此端口。

如需启动前填写配置，将 `server.config.example.json` 复制为 `server.config.json`，填好 token；示例文件不是自动读取的配置。SMTP 未配置时验证码只输出在服务器控制台，团队自助注册需要配置 SMTP。服务当前监听 `0.0.0.0`；默认空 token 不限制 API，首次部署应在可信内网完成并设置令牌。当前协议授权的其他已知问题见工程待办，不建议直接暴露公网。

## 升级

客户端自动更新不会升级这台服务器。管理员下载同一个 Release 中的新服务器 ZIP，并执行：

1. 停止服务器（控制台 Ctrl+C；作为服务运行则停止该服务）。
2. 完整备份原目录，尤其是 `server.config.json`、`server-data/`，以及配置的自定义数据库和备份路径。
3. 用新 ZIP 替换代码、启动脚本和 `VERSION.json`，保留实际配置和数据。服务初始化会补充所需表字段；不清空原数据。
4. 重启，检查管理台与成员连接。回退时同时恢复备份代码和数据库。

需要持续运行时可由管理员将 `node server.js` 注册到操作系统服务或现有进程管理器，工作目录设为解压目录；只运行一份实例。进程管理器不随包附带。
